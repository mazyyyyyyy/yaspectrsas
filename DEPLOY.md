# Установка на Synology DSM (Container Manager)

Приложение поднимается тремя контейнерами: PostgreSQL, API и веб (nginx).
Наружу торчит только веб — на **порту 8324**. Всё остальное общается внутри
приватной сети проекта.

При старте API сам приводит базу в порядок: применяет миграции, накатывает
политики Row-Level Security и один раз наполняет справочник стартовыми данными.
Никаких ручных SQL-команд запускать не нужно.

---

## Вариант 1. Через Container Manager (графический интерфейс)

1. **Скопируйте проект на NAS.** Через File Station положите папку проекта,
   например в `/volume1/docker/yaspectr`. Проще всего клонировать репозиторий
   или распаковать в неё архив — важно, чтобы рядом лежали `docker-compose.yml`,
   папки `apps/` и `packages/`.

2. **Создайте файл `.env`.** Скопируйте `.env.docker.example` в `.env` в той же
   папке и при желании поменяйте пароль БД и `SESSION_SECRET`. Обязательно
   впишите в `CORS_ORIGINS` адрес, по которому будете открывать приложение,
   например:

   ```
   CORS_ORIGINS=http://192.168.1.50:8324
   ```

   (замените на реальный IP или имя вашего Synology).

3. **Container Manager → Проект → Создать.**
   - Имя проекта: `yaspectr`
   - Путь: папка из шага 1 (`/volume1/docker/yaspectr`)
   - Источник: **Использовать существующий `docker-compose.yml`**
   - Нажмите «Далее» и подтвердите сборку.

4. Дождитесь, пока соберутся образы и поднимутся контейнеры (первый раз это
   несколько минут — собираются фронт и бэкенд).

5. Откройте в браузере `http://<IP-вашего-NAS>:8324`.

## Вариант 2. Через SSH (командная строка)

```sh
cd /volume1/docker/yaspectr
cp .env.docker.example .env      # при желании отредактируйте
# впишите свой адрес в CORS_ORIGINS внутри .env

sudo docker compose up -d --build
```

Проверить, что всё поднялось:

```sh
sudo docker compose ps
sudo docker compose logs -f api      # здесь виден пароль администратора (см. ниже)
```

## Первый вход

При самом первом запуске (пустая база) сидинг создаёт администратора и
**один раз** печатает его пароль в лог контейнера `api`. Найдите его:

- в Container Manager: контейнер `yaspectr-api-1` → вкладка **Журнал**;
- по SSH: `sudo docker compose logs api | grep -A2 "Вход в систему"`.

Строки выглядят так:

```
  Вход в систему:
    email:  admin@yaspectr.local
    пароль: <здесь-случайный-пароль>
```

Сохраните пароль — второй раз он не показывается. Сменить его можно уже внутри
приложения.

## Обновление до новой версии

```sh
cd /volume1/docker/yaspectr
git pull                 # или обновите файлы вручную
sudo docker compose up -d --build
```

Данные в базе сохраняются — они лежат в docker-томе `pgdata`, пересборка их не
трогает. Миграции применяются автоматически при старте.

---

## Резервная копия базы

```sh
# бэкап
sudo docker compose exec db pg_dump -U yaspectr yaspectr > yaspectr-backup.sql

# восстановление
cat yaspectr-backup.sql | sudo docker compose exec -T db psql -U yaspectr yaspectr
```

## Публикация в интернет (HTTPS)

По умолчанию всё настроено на работу в локальной сети по HTTP (порт 8324).
Приложение при этом работает в режиме `development`, потому что его собственная
проверка конфигурации намеренно запрещает `production` без HTTPS (иначе
cookie-сессия «уехала» бы по незащищённому каналу).

Если открываете приложение наружу — поставьте перед ним HTTPS. На Synology
проще всего через **Control Panel → Login Portal → Advanced → Reverse Proxy**
(или через свой домен и сертификат Let's Encrypt), направив внешний
`https://ваш-домен` на `localhost:8324`. После этого в `docker-compose.yml`
для сервиса `api` переключите режим на боевой:

```yaml
    environment:
      NODE_ENV: production
      COOKIE_SECURE: "true"
      CORS_ORIGINS: https://ваш-домен      # обязательно https, без слеша на конце
      SESSION_SECRET: <не короче 43 символов>
```

и пересоберите: `sudo docker compose up -d --build`.

## Что где слушает

| Контейнер | Порт внутри сети | Наружу            |
|-----------|------------------|-------------------|
| `web`     | 80 (nginx)       | **8324**          |
| `api`     | 3000             | — (только внутри) |
| `db`      | 5432             | — (только внутри) |

Веб-контейнер отдаёт статику приложения и проксирует все запросы `/api` в
контейнер `api`, поэтому для браузера фронт и бэкенд — один источник, и
cookie-сессия работает без послаблений в CORS.
