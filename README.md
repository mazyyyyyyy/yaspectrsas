# Яспектр — сметы и акты для монтажа систем безопасности

Расчёт смет и акты выполненных работ: экспресс-прикидка у клиента на объекте,
детальная смета «до винтика», чек-лист для монтажника. PWA — работает в браузере
на компьютере, планшете и телефоне, ставится иконкой на домашний экран.

## Главная идея

**Три поверхности, один расчёт.** Экспресс-режим, детальная смета и печатный
документ — это не три программы, а три вида одних и тех же данных. Движок
расчёта вынесен в отдельный пакет `packages/core`, который импортируют и
браузер, и сервер, и генератор PDF. Поэтому сумма на телефоне у клиента,
сумма в развёрнутой смете и сумма в PDF физически не могут разойтись.

**Позиция → комплект.** У базовой позиции (камера, точка Wi-Fi, домофон) есть
шаблон комплекта: монтаж, юстировка, распред. коробка, кабель. Добавляя
«6 камер» одним действием, вы получаете весь комплект с посчитанными
количествами — кабель сам станет 180 м при норме 30 м на точку.

**Кабель не особый случай.** У каждой позиции справочника ДВЕ цены: за материал
и за работу. У кабеля это «цена за метр» и «цена за метр прокладки» — одна
запись, две цены. Побочный выигрыш: разбивка «Материалы / Работы» в итогах
получается точной, а не прикидочной.

**Иконку выбирает человек.** 53 значка под слаботочку — видеонаблюдение, СКУД,
домофония, ОПС, сеть, питание, кабель, работы — с поиском по разговорным словам
(«геркон» находит магнитоконтактный извещатель). Реестр в
`packages/core/src/icons.ts`, формы в `apps/web/src/catalog-icons.tsx`; сервер
проверяет, что пришёл известный идентификатор. При вводе названия иконка
подставляется подсказкой, но хранится всегда явный выбор: выводить значок из
названия — значит не уметь объяснить пользователю, почему он такой, и менять
его при переименовании позиции.

## Структура

```
packages/core     Домен, Zod-схемы, движок расчёта. Чистые функции, никакого I/O.
apps/api          NestJS + Fastify + Prisma + PostgreSQL.
apps/web          React + Vite + PWA.
```

## Первый запуск

Нужны Node 20+ и PostgreSQL 14+.

```bash
npm install
```

### 1. База данных

Роль приложения намеренно **не суперпользователь**: в `rls.sql` включён
`FORCE ROW LEVEL SECURITY`, и политики изоляции тенантов действуют даже на
владельца базы. Суперпользователь обошёл бы их, и защита осталась бы на бумаге.

```sql
CREATE ROLE yaspectr LOGIN PASSWORD 'ваш_пароль';
CREATE DATABASE yaspectr OWNER yaspectr;
-- Только для `prisma migrate dev` в разработке. На проде не нужна.
CREATE DATABASE yaspectr_shadow OWNER yaspectr;
```

### 2. Конфигурация

```bash
cp .env.example apps/api/.env
```

Заполнить `DATABASE_URL` и сгенерировать секрет сессий:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

API проверяет конфигурацию при старте и **отказывается подниматься** с опасными
настройками: пустой `SESSION_SECRET`, `CORS_ORIGINS=*`, а в production ещё и
`COOKIE_SECURE=false` или источник по `http://`.

### 3. Миграции, изоляция, данные

```bash
cd apps/api
npx prisma migrate dev            # таблицы
psql "$DATABASE_URL" -f prisma/rls.sql   # политики изоляции тенантов
npm run db:seed                   # справочник, комплекты, администратор
```

Seed кладёт рабочий стартовый набор: 8 категорий, 65 позиций (видеонаблюдение,
СКУД, домофония, ОПС, сеть, питание, расходники, работы) и 7 комплектов
«под ключ». Цены — ориентир по рынку, их правят под своих поставщиков.

Seed напечатает пароль администратора **один раз** — сохраните его.

> `rls.sql` применяется после каждого `prisma migrate deploy`: миграции Prisma
> не знают о политиках и не пересоздают их.

### 4. Запуск

```bash
npm run dev:api    # http://localhost:3000
npm run dev:web    # http://localhost:5173
```

Vite проксирует `/api` на бэкенд, поэтому браузер считает их одним источником и
cookie-сессия работает без послаблений в CORS.

## Безопасность

Что сделано и почему именно так:

| Решение | Причина |
|---|---|
| **argon2id** для паролей | Не bcrypt (лимит 72 байта, слабее против GPU) и тем более не SHA-256. Параметры — минимум OWASP: 19 МиБ, 2 прохода. |
| **Непрозрачные токены сессий**, а не JWT | JWT нельзя отозвать до истечения срока. «Уволенный сотрудник ходит в систему ещё сутки» — не теория. |
| Сессия в **httpOnly-cookie** | Скрипт её не прочитает даже при XSS. В localStorage токен крадётся одной строкой. |
| **CSRF: double submit + HMAC** | Токен выводится из сессии через HMAC и сверяется сравнением постоянного времени. Чужой сайт не может прочитать cookie и подставить заголовок. |
| **Zod `.strict()`** на каждом входе | Лишние поля отвергаются: нельзя дописать в тело запроса `companyId` или `status` и протащить их в БД. |
| **RLS в PostgreSQL** | Второй рубеж поверх явного `companyId`. Запрос в обход `runAsTenant` возвращает ноль строк, а не чужие данные. |
| Закупочные цены **вырезаются на сервере** | Монтажник не видит маржу. Спрятанная кнопка защитой не является — ответ API открывается в консоли за две секунды. |
| **Снимок цен** в смете | Поставщик поднял цену — отправленная клиенту смета не меняется задним числом. |
| Блокировка после 5 неудач + **одинаковый ответ** на неверный логин и пароль | Иначе форма входа превращается в справочник зарегистрированных адресов. |
| Печать PDF **без JS и без сети** | Данные пользователя экранируются, но печать — это исполнение недоверенного контента в браузере, и одного экранирования мало. |

Роли: **ADMIN** (справочник, комплекты, пользователи), **MANAGER** (сметы, акты),
**INSTALLER** (свои акты; смету видит, править не может; закупочные цены не видит
никогда). Таблица прав — одна на фронт и бэк, в `packages/core/src/domain.ts`.

## Проверка

```bash
npm test          # 85 тестов ядра + 31 тест безопасности API
npm run typecheck
npm run build
```

Тесты ядра покрывают то, что ломается тихо: округление денег, разворот
комплектов, сохранение ручных правок при пересчёте, разделение материалов и
работ.

## Что осталось за рамками

- **Telegram-бот** для отправки актов — модель под него готова (таблица
  `telegram_chats`, куда бот отправляет, — закрытый список: пользователь выбирает
  из привязанных чатов и не может подставить произвольный `chatId`, иначе акт с
  адресом объекта уедет куда угодно).
- **Docker-развёртывание** — приложение к нему готово (вся конфигурация через
  переменные окружения, никаких managed-сервисов), но `docker-compose.yml` не
  написан.
- **Редактор комплектов в интерфейсе** — API `POST/PATCH /api/kits` работает,
  экран показывает комплекты только на чтение.
